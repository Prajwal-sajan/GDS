Integration APIs
List Of APIs

Below are the mandatory APIs for integrating.

Search
Source Destination and DOJ based API to give all active inventory for the DOJ 

SeatlayoutSeatlayout Details for a particular service

Tentative Booking
Tentative seat blocking API for a service 

Confirm Booking
Confirm Seats API

Cancel Ticket
Cancel ticket API to cancel seats, it can be full cancellation or partial cancellation 

Cities and Source-Destinations
API that List Cities and API that lists active Source Destinations for an operator

Ticket Details
Given a PNR return ticket details

Check PNR
In case the Confirm Booking API fails we will call this API to check if PNR is booked at GDS end.

Update Booking
Post booking customer is given an option to update Phone No, Boarding Point and Dropping Point

Trip Status
To check if the customer has boarded or not boarded the bus. 

Release Seats
If is customer does only tentative booking and does not do a confirm booking we will release seats for the blocked seats

10. Trip Status
Trip Status
API to check if the passenger has boarded or not boarded. 
Method : POST
Url :http://apidns/tripstatus

Request:
{
"pnr": "PNR",
"Operator_id":"Unique identifier", // Optional,
}
Response:
[
{
"pnr_number": "UNQ1218073",
"status": "Boarded/No-Show/Yet-To-Board",
"seat_number": "2G",
"time": "2025-10-18 05:30:23"
},
{
"pnr_number": "UNQ1218073",
"status": "Boarded",
"seat_number": "2F",
"time": "2025-10-18 05:30:23"
}
]
Definition of Status
Boarded: Customer boarded the bus
No-Show: The customer didn’t board the bus for sure.
Yet-To-Board: Not sure about boarding status, bus operators didn’t mark for sure.

Callback APIs
List OfCallback APIs

Below are the APIs where the GDS will call Redbus APIs to send events on inventory updates and post booking updates.

Cities/SD
For any New addition of city or a source destination combination for an operator. It’s a one time addition. 

SearchFor any inventory addition or update happening at an Source Destination DOJ level.
Inventory Update
For any inventory update happening at a single bus level.

Inactive Services
To remove any inactive inventory or any soldout inventory.

Bus Cancellation
To update tickets and refund customer when bus is cancelled

Bus Shift
Ticket Update events done by the operator, includes events like if any bus is shifted or DOJ is changed or boarding point change, boarding time change.

6. Bus Shift
BUS SHIFT

This feature addresses the Bus Shift process, where bus operators move passengers from one service to another in cases like low occupancy or bus breakdowns. Today, this happens manually with refunds, calls, and ad-hoc arrangements, leading to inefficiencies and poor customer experience. The API-based solution will standardize and automate this shifting workflow within the GDS, ensuring smoother operations for operators and transparency for customers. 
Purpose: Facilitate automated bus shifting through GDS alerts
Method: POST

URL :http://redbus-domain-name?action_type=SHIFT
Action type: SHIFT
Method : POST
