# Modern JourneyOS GDS — Schedule Bookings Share (v3)

## User-visible behavior

Schedules → Manage → Bookings → **Share booking link** fetches the **current operator route/date passenger search URL** via an authenticated ASP.NET Core request, then copies this exact kind of message:

Hyderabad → Bengaluru on Sun, 22 Nov, 2026 — pick your seat and book: https://novembertravels.com/bus/search/?fromCity=107258&toCity=102257&journeyDate=2026-11-22

This example is the operator screenshot reference from the legacy v50 audit, **not a preconfigured production site**. Never enable November Travels as another operator's URL. The user-visible booking URL is an **operator-specific route/date search**, not a guaranteed deep link into one particular bus; the passenger website selects which available services to display.

## Required operator configuration

No default booking website is enabled. Operator admins must first verify their official passenger site supports **exactly** the three documented query parameters: fromCity, toCity and journeyDate.

Configure ASP.NET Core environment variables (replace tenant code, website and IDs with those verified for the actual operator):

- PublicBooking__Operators__demo__SearchUrl = https://your-authorized-operator-domain.example/bus/search/
- PublicBooking__Operators__demo__CityMap__107258 = 107258
- PublicBooking__Operators__demo__CityMap__102257 = 102257

The domain shown above ends in .example and **must never be used in production**. The keys to CityMap are internal source city IDs; the values are the booking website's confirmed IDs. They are not automatically assumed to match.

On Windows PowerShell, for a **local controlled test only**, this is the exact environment variable syntax:

~~~powershell
$env:PublicBooking__Operators__demo__SearchUrl = "https://your-real-authorized-booking-website.com/bus/search/"
$env:PublicBooking__Operators__demo__CityMap__107258 = "107258"
$env:PublicBooking__Operators__demo__CityMap__102257 = "102257"
~~~

Restart ASP.NET after applying operator configuration. Do not check in a live domain that belongs to another operator or add secrets to documentation. **Current limitation:** these values are configured server-side; the legacy Settings → Website editor has not been migrated into the modern app.

## Technical and safety rules

- Endpoint: GET /api/admin/trips/{tripId}/share-link?fromSequence=...&toSequence=... (Operations policy, authenticated tenant).
- Trip must be active and bookable; selected cities must belong to the same trip and have increasing route-stop sequences.
- The boarding date is trip.TravelDate + (selected-origin day number − 1). This preserves Day-2 and later boarding dates.
- Past boarding times are rejected using the operator's configured time zone; invalid status or missing booking site/mappings returns an actionable error.
- Public booking site must be HTTPS, public DNS hostname, no login credentials, non-default port, query, or fragment. localhost/IP/private hostnames are rejected.
- No PNR, staff data, customer contacts, auth headers, phone, OTP or passenger details are included in the shared text.
- No calls to the passenger website are made from the GDS Share endpoint. The browser/WhatsApp preview is generated by the **passenger website's own** Open Graph metadata; our API does not control it.
- ClipboardItem with a promise-backed text/plain Blob is attempted synchronously in the click handler to preserve browser user activation. Clipboard denial exposes a selected textarea for Ctrl+C. A "copied" status appears only after clipboard write succeeds.
- No seats are blocked, held or booked by requesting or copying the URL.

## Acceptance tests

~~~powershell
cd D:\GDS\modern\frontend
npm ci
npm run build
npx playwright test e2e\schedules-parity.spec.ts
~~~

The .NET tests verify URL safety, the reference message format, PostgreSQL tenant-isolated route data, configured end-to-end HTTP route and missing configuration. Playwright tests verify the Share click and permission fallback.

**Production UAT still required:** use an operator-approved domain and city mappings; inspect the destination site with an actual future trip and selected Day-2 boarding point; confirm date/route are prepopulated and the website lists only its real authorized services.
